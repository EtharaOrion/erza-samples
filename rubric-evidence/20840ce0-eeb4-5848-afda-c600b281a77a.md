## Doctrine

PROMPT-AUTHOR-TO-30.md Stage-6 / 6.11: weight magnitudes strictly in {5,3,1,0}; guardrails negative; narration capped at 1; one test_<id> per deterministic criterion; every truth_ref resolves to a heading in the CURRENT TRUTH.md (enforced by verification/check_refs.py). Every weight carries a weight_evidence receipt naming either a measured control in ../expected_values.json:control_gaps or the structural role it guards.

## Gate doctrine

ONE criterion gates: d_places_payee_block_at_published_offsets, the crux the task exists to measure. 6.11 objects that no shipped deliverable declares a gate, so a run that failed the load-bearing step still prints an uncapped number; score.py caps final at 0.5 and labels CRUX-FAILED when a gate scores 0. The detector is numeric rather than lexical - a literal reading as the first payee name line's published start AND one reading as the payee city's published start, at either the one-based or the zero-based spelling, appearing where they can act; or six distinct published late start positions written out - which is the tightest evidence available before a pilot, and it is exercised in both directions by verification/negative_fixtures_test.py. The caveat this doctrine previously recorded - that a correct run concatenating fields by LENGTH, never writing an absolute offset, would fail the detector and produce a false CRUX-FAILED on a sound trajectory - is REPAIRED as of 2026-08-03 rather than merely disclosed. TRUTH.md Step 5 blesses that spelling in as many words and calls neither safer, so binding the gate to the offset spelling was a route restriction (REQUIREMENTS.md:324-341) sitting on the one criterion that can cap a run's score. The detector now also accepts an ordered length table that keeps both interior reserved runs and carries the payee block's own rows. It is the reserved rows that decide, not the vocabulary: the same table with those rows deleted is the packed record the crux exists to catch, and verification/negative_fixtures_test.py shows the route accepted by the whole suite and the closed-run variant still rejected by both crux surfaces. No judged criterion gates: panel noise disqualifies a judged criterion from a verdict-flipping role.

## Per-criterion weight evidence

### `d_reads_inputs`  (deterministic, weight 1)

Structural role: orientation precondition. The specification's identity, revision, record length and return type all live in question.json, and every graded field is a property of a payee entry, so a run that never opens the inputs cannot be building the right record. Hygiene tier (weight 1): low blast radius alone, but everything downstream depends on it.

### `d_writes_emitter`  (deterministic, weight 1)

Structural role: three records of 750 positions across some fifty fields each cannot be typed correctly inside the budget. Hygiene tier (weight 1); it constrains how the work is done, not what is known.

### `d_executes_emitter`  (deterministic, weight 1)

Structural role: separates a produced artifact from an unrun draft. Hygiene tier (weight 1).

### `d_pins_the_declared_length`  (deterministic, weight 1)

Structural role: the length is stated in question.json, so this discriminates careless reading rather than withheld knowledge. It guards the one graded case a well-formed but empty submission can reach - the answer-file shape case - and nothing else. Hygiene tier (weight 1).

### `d_places_payee_block_at_published_offsets`  (deterministic, weight 5, GATE)

Crux (TRUTH.md Step 5), and the Delta-lever in one criterion. The measured control shifted_name_and_address_block - the nearest real competitor, which places the opening and the amounts correctly and then closes the reserved runs - separates by 6x tolerance on its widest group and fails 24 of 31 graded cases (control_gaps.shifted_name_and_address_block). Weight 5, and the only gate in this bundle. ROUTE INDEPENDENCE (repaired 2026-08-03): the detector formerly required an absolute start-position literal, so a run that concatenated the fields by LENGTH - fully correct, since the fields are contiguous and this bundle's own sibling d_reserves_the_interior_runs already admits that spelling - scored 0 on the gate and was reported CRUX-FAILED. That is the route restriction REQUIREMENTS.md:324-341 forbids, and it fell hardest on the no-Skills arm, which is the arm most likely to reach for a plain (name, width) table. The length route is admitted only when both interior reserved rows are present, so it accepts the route without accepting the packed record: verification/negative_fixtures_test.py runs the concatenation route against the whole suite and shows the same route with the reserved rows deleted still rejected.

### `d_reserves_the_interior_runs`  (deterministic, weight 5)

Crux surface 1 (TRUTH.md 'The crux'). Closing either interior run is exactly what produces shifted_name_and_address_block: a well-formed line of the right length with the opening correct and every field after the first closed run displaced, failing 24 of 31 graded cases. Weight 5. Not gated: its second admissible spelling - a length-table concatenation naming the run - is the softer of the two crux detectors.

### `d_emits_return_specific_tail`  (deterministic, weight 3)

Measured control missing_form_specific_tail separates by 4x tolerance and fails 9 of 31 graded cases (control_gaps.missing_form_specific_tail). The neighbouring form's tail, nec_tail_instead_of_misc, is measured at 2x on one payee and NON-DISCRIMINATING on the other two, which is why this criterion is weighted for placing the tail at all rather than for picking between two nearly identical tails. Weight 3: an outcome-breaking placement error over part of the record, not the step the whole task rests on. COVERAGE (added 2026-08-03): this criterion also names Step 2, which no truth_ref reached and which carried no uncheckable declaration - instrument blindness on a step, and in a score artifact blindness is indistinguishable from coverage (REQUIREMENTS.md:317-322). Step 2 is 'retrieve the field table for this record and this return type', and its return-type half is exactly what this criterion evidences: the tail indicator and the programme-code position, or the 114-wide reserved run and the 60-wide free-text field, exist only in the per-form table, so a run holding them retrieved it. A separate criterion was deliberately NOT added: Step 2's only observable consequence is the return-specific tail, and a second row decided by the same evidence would charge one question twice and silently double its weight mass, which REQUIREMENTS.md:311-316 forbids. The common half of Step 2 is evidenced by the crux criterion's position set. ROUTE INDEPENDENCE (repaired the same day): the length-table spelling was added here for the same reason as on the crux - a route the crux blesses that a sibling rejects is a defect in the instrument, not in the run (REQUIREMENTS.md:337-341).

### `d_amount_fields_right_justified_zero_filled`  (deterministic, weight 3)

Measured control left_justified_amount_fields separates by 36x tolerance on its widest group and fails 9 of 31 graded cases (control_gaps.left_justified_amount_fields). Weight 3 rather than 5 deliberately: this convention is the part of the specification a model reproduces unaided, so it is a real outcome-breaking error but it is NOT the withheld knowledge, and the task is built so that it cannot carry the separation - test_outputs.py::test_amount_convention_alone_does_not_carry_the_task asserts that bound.

### `d_sequence_number_zero_filled`  (deterministic, weight 1)

Structural role: one field of one graded group, and the same field-class rule the amount fields already exercise, so it adds detail rather than discrimination. Hygiene tier (weight 1).

### `d_converts_amounts_to_cents`  (deterministic, weight 1)

Structural role: arithmetic the prompt's own units make obvious, discriminating carelessness rather than knowledge. It is folded into the same graded group as the amount padding, so it moves no case on its own. Hygiene tier (weight 1).

### `d_reports_contract`  (deterministic, weight 1)

Structural role: a correctly placed record that misses the contract is unscoreable, so this guards measurability rather than knowledge. Hygiene tier (weight 1).

### `d_g_delimited_output`  (deterministic, weight -3)

Measured control comma_delimited_instead_of_fixed_width separates by 36x tolerance and fails 30 of 31 graded cases (control_gaps.comma_delimited_instead_of_fixed_width) - the largest of the recorded routes. Guardrails are negative by design; magnitude 3 rather than 5 because the input labels the orientation block honestly and copying it is a distinct, attributable behaviour rather than the crux failure itself.

### `d_g_padded_remainder_without_placing`  (deterministic, weight -5)

Crux surface 3, and the route the recall measurement predicts: reproduction of this specification is real for the opening fields and decays after the payment amount block. It is the hardest failure to see, because what it produces is a well-formed line of exactly the right length. Its nearest measured relative, missing_form_specific_tail, already separates by 4x while placing far more of the record. Magnitude 5 matches the crux tier it negates.

### `d_g_grader_path_access`  (deterministic, weight -5)

Structural integrity: any hit invalidates the pair regardless of score, and on this task the grading surface literally contains the withheld field table. Containment is enforced by file ownership in the image and by sandbox_locked_paths; this criterion records whether it was tested. Magnitude matches the crux tier because a hit voids the measurement rather than degrading it.

### `d_g_network_egress`  (deterministic, weight -3)

Structural integrity, and on this task it is load-bearing rather than hygienic: the withheld object is a published table on a public URL and it CANNOT be anonymised, so an unblocked fetch hands over the lever itself. This is recorded honestly in build_report.json:anonymisation as the bundle's principal residual risk, and the pilot must run with the egress firewall enabled and per-run evidence of it. Magnitude 3 rather than 5 because citing the source URL beside the positions typed from it is attribution, not egress, and the detector requires a fetch verb.

### `n_treats_positions_as_absolute`  (non_deterministic, weight 1)

Narration tier, capped at 1 by doctrine. It was drafted at 3 as the judged twin of d_places_payee_block_at_published_offsets - shifted_name_and_address_block (6x tolerance, 24 of 31 cases) is precisely this confusion - but what it asks the judge for is what the run SAYS about the layout, and a model can say it without doing it. The behaviour itself is already scored where it leaves a work product: the crux criterion carries weight 5, gates, and tests it numerically. Re-tiering costs the instrument nothing and removes a double count.

### `n_verification_that_can_disagree`  (non_deterministic, weight 3)

Behavioural: every failure route on this task returns a well-formed line of the declared length made of admissible characters, so nothing about the output looks wrong and only a check that can disagree separates a correctly placed record from a confidently misplaced one. Weight 3 (an executed check is a work product, not a claim).

### `n_states_layout_source`  (non_deterministic, weight 1)

Narration tier: a speech act any style-tuned model can emit, capped at weight 1 by doctrine. Its value is attribution - it lets a reviewer bind a wrong record to a named route, and it is what distinguishes a cited table from one the run produced without a source, which matters here because a frequent and false claim about this family of specifications is that the fixed-length format has been retired.
